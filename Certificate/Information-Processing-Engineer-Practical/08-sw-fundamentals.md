## 2. 프로세스와 스레드

### 2.1 프로세스

실행 중인 프로그램이다.

프로세스마다 독립적인 메모리 공간을 가진다.

### 2.2 스레드

프로세스 내부의 실행 흐름이다.

같은 프로세스의 스레드끼리 공유하는 영역:

```text
코드 영역
데이터 영역
힙 영역
```

스레드마다 별도로 가지는 영역:

```text
스택
프로그램 카운터
레지스터
```

### 비교

| 프로세스 | 스레드 |
|---|---|
| 독립적인 메모리 공간 | 프로세스 자원을 공유 |
| 생성·전환 비용이 큼 | 생성·전환 비용이 상대적으로 작음 |
| 프로세스 간 통신 필요 | 공유 자원으로 통신 가능 |
| 한 프로세스 오류가 다른 프로세스에 미치는 영향이 작음 | 한 스레드 오류가 같은 프로세스에 영향을 줄 수 있음 |

## 3. 프로세스 상태

```text
생성(New)
→ 준비(Ready)
→ 실행(Running)
→ 대기(Waiting/Blocked)
→ 종료(Terminated)
```

| 상태 전이 | 의미 |
|---|---|
| 준비 → 실행 | 디스패치 |
| 실행 → 준비 | 시간 할당량 종료 또는 선점 |
| 실행 → 대기 | 입출력 요청 |
| 대기 → 준비 | 입출력 완료 |
| 실행 → 종료 | 작업 완료 |

### PCB(Process Control Block)

운영체제가 프로세스를 관리하기 위해 저장하는 정보다.

주요 내용:

- 프로세스 ID
- 프로세스 상태
- 프로그램 카운터
- CPU 레지스터
- 스케줄링 정보
- 메모리 관리 정보
- 입출력 상태 정보

### 문맥 교환(Context Switching)

CPU가 실행할 프로세스를 변경할 때 현재 프로세스의 상태를 저장하고 다음 프로세스의 상태를 복원하는 작업이다.

## 4. 인터럽트와 시스템 콜

### 4.1 인터럽트

CPU가 현재 작업을 중단하고 우선 처리해야 할 사건을 처리하도록 알리는 신호다.

| 종류 | 예 |
|---|---|
| 외부 인터럽트 | 키보드 입력, 타이머, 입출력 완료 |
| 내부 인터럽트 | 0으로 나누기, 잘못된 명령 |
| 소프트웨어 인터럽트 | 시스템 콜 |

### 4.2 시스템 콜

사용자 프로그램이 운영체제 커널의 기능을 요청하는 인터페이스다.

예시:

```text
파일 열기
프로세스 생성
메모리 할당
입출력 요청
```

## 5. 동기화

### 5.1 임계 구역(Critical Section)

여러 프로세스나 스레드가 동시에 접근하면 문제가 발생할 수 있는 공유 자원 접근 코드 영역이다.

임계 구역 문제 해결 조건:

```text
상호 배제
진행
한정 대기
```

### 5.2 뮤텍스(Mutex)

한 번에 하나의 스레드만 공유 자원에 접근하도록 하는 잠금 방식이다.

### 5.3 세마포어(Semaphore)

정수형 값을 이용해 공유 자원에 접근할 수 있는 프로세스 수를 제어한다.

| 종류 | 의미 |
|---|---|
| 이진 세마포어 | 값이 0 또는 1 |
| 계수 세마포어 | 여러 개의 동일 자원 관리 |

### 5.4 모니터(Monitor)

공유 자원과 해당 자원에 접근하는 연산을 하나로 묶고 자동으로 상호 배제를 제공한다.

## 6. 교착상태

둘 이상의 프로세스가 서로가 가진 자원을 기다리면서 영원히 진행하지 못하는 상태다.

### 발생 조건

```text
상호 배제
점유와 대기
비선점
순환 대기
```

암기:

```text
상점비순
```

### 해결 방법

| 방법 | 의미 |
|---|---|
| 예방 | 발생 조건 중 하나를 제거 |
| 회피 | 안전 상태만 허용, 은행원 알고리즘 사용 |
| 탐지 | 교착상태 발생 여부를 주기적으로 검사 |
| 회복 | 프로세스 종료 또는 자원 강제 회수 |

## 7. 메모리 관리

### 7.1 페이징

프로세스를 고정 크기의 페이지로, 물리 메모리를 같은 크기의 프레임으로 나눈다.

```text
장점: 외부 단편화 감소
단점: 내부 단편화 발생 가능
```

### 7.2 세그먼테이션

프로그램을 코드, 데이터, 스택처럼 의미 있는 가변 크기 단위로 나눈다.

```text
장점: 프로그램의 논리 구조 반영
단점: 외부 단편화 발생 가능
```

### 비교

| 페이징 | 세그먼테이션 |
|---|---|
| 고정 크기 | 가변 크기 |
| 페이지와 프레임 | 세그먼트 |
| 내부 단편화 가능 | 외부 단편화 가능 |
| 물리적 메모리 관리 중심 | 논리적 프로그램 단위 중심 |

### 내부 단편화와 외부 단편화

| 구분 | 의미 |
|---|---|
| 내부 단편화 | 할당된 공간 내부에 사용하지 못하는 공간 발생 |
| 외부 단편화 | 빈 공간은 충분하지만 여러 곳에 흩어져 할당 불가 |

## 8. 가상 메모리

프로그램 전체를 메모리에 올리지 않고 필요한 부분만 적재하여 실제 메모리보다 큰 프로그램을 실행하는 기술이다.

### 8.1 요구 페이징

필요한 페이지가 참조될 때 메모리에 적재한다.

### 8.2 페이지 부재(Page Fault)

참조한 페이지가 메모리에 없을 때 발생한다.

### 8.3 스래싱(Thrashing)

페이지 교체가 지나치게 자주 발생해 실제 작업보다 페이지 교체에 더 많은 시간을 소비하는 현상이다.

주요 원인:

```text
프로세스에 할당된 프레임 부족
지나치게 많은 프로세스 실행
```

### 관련 개념

- **지역성(Locality)**: 가까운 시간이나 주소의 데이터가 다시 참조될 가능성이 높다는 성질
- **워킹 세트(Working Set)**: 일정 시간 동안 자주 참조되는 페이지 집합

## 9. 페이지 교체 알고리즘

| 알고리즘 | 교체 기준 |
|---|---|
| FIFO | 가장 먼저 들어온 페이지 |
| OPT | 앞으로 가장 늦게 사용될 페이지 |
| LRU | 가장 오랫동안 사용하지 않은 페이지 |
| LFU | 사용 횟수가 가장 적은 페이지 |
| MFU | 사용 횟수가 가장 많은 페이지 |
| NUR | 참조 비트와 수정 비트 이용 |
| SCR | FIFO에 두 번째 기회를 부여 |

### 벨레이디 이상

프레임 수를 늘렸는데 페이지 부재 횟수가 증가하는 현상이다.

```text
대표적으로 FIFO에서 발생할 수 있다.
```

### NUR 우선순위

참조 비트 `R`, 수정 비트 `M`:

```text
(0,0) → (0,1) → (1,0) → (1,1)
```

왼쪽에 있는 상태일수록 교체 우선순위가 높다.

## 11. OSI 7계층

```text
응용 → 표현 → 세션 → 전송 → 네트워크 → 데이터링크 → 물리
```

암기:

```text
응표세전네데물
```

| 계층 | 핵심 기능 및 프로토콜 |
|---:|---|
| 7 응용 | HTTP, FTP, SMTP, DNS |
| 6 표현 | 압축, 암호화, 인코딩 |
| 5 세션 | 연결 설정, 동기화, 대화 제어 |
| 4 전송 | TCP, UDP, 포트 |
| 3 네트워크 | IP, 라우팅, 라우터 |
| 2 데이터링크 | 프레임, MAC, 스위치 |
| 1 물리 | 비트, 케이블, 허브, 리피터 |

### PDU

```text
응용·표현·세션 계층 → 데이터
전송 계층 → 세그먼트 또는 데이터그램
네트워크 계층 → 패킷
데이터링크 계층 → 프레임
물리 계층 → 비트
```

## 12. TCP와 UDP

| TCP | UDP |
|---|---|
| 연결형 | 비연결형 |
| 신뢰성 있음 | 신뢰성을 보장하지 않음 |
| 순서 보장 | 순서를 보장하지 않음 |
| 흐름·오류·혼잡 제어 | 제어 기능이 단순 |
| 상대적으로 느림 | 빠름 |
| 파일 전송, 웹, 이메일 | 스트리밍, DNS, 실시간 통신 |

### TCP 3-way Handshake

```text
클라이언트 → SYN
서버 → SYN + ACK
클라이언트 → ACK
```

### TCP 연결 종료

일반적으로 다음 순서로 진행된다.

```text
FIN → ACK → FIN → ACK
```

## 15. 오류 검출 및 정정

### 15.1 패리티 검사

데이터에 검사 비트 1개를 추가한다.

- 짝수 패리티
- 홀수 패리티

오류 검출은 가능하지만 일반적으로 오류 위치를 찾거나 수정하기 어렵다.

### 15.2 CRC

송신자와 수신자가 동일한 생성 다항식을 이용해 오류를 검출한다.

```text
연속적으로 발생한 오류 검출에 강하다.
```

### 15.3 해밍 코드

검사 비트를 여러 개 추가하여 오류 위치를 찾고 수정할 수 있다.

### 15.4 FEC와 BEC

| 방식 | 의미 |
|---|---|
| FEC | 수신 측에서 재전송 없이 오류를 직접 수정 |
| BEC | 오류 발생 시 송신 측에 재전송 요청 |

```text
해밍 코드 → FEC
재전송 요청 → BEC
```

## 16. 보안 공격

### 16.1 SYN 플러딩

TCP 3-way Handshake의 연결 대기 상태를 악용한다.

```text
다량의 SYN 전송
→ 서버가 SYN+ACK 응답
→ 마지막 ACK를 보내지 않음
→ 서버의 연결 대기 자원 고갈
```

### 16.2 스푸핑과 스니핑

| 용어 | 의미 |
|---|---|
| 스푸핑 | 신원이나 주소를 다른 것처럼 위조 |
| 스니핑 | 네트워크 패킷을 몰래 가로채 관찰 |
| 세션 하이재킹 | 정상 사용자의 세션 탈취 |
| ARP 스푸핑 | 위조된 ARP 정보를 보내 통신을 가로챔 |
| DNS 스푸핑 | 잘못된 DNS 응답으로 가짜 사이트 유도 |

### 16.3 기타 공격

| 공격 | 의미 |
|---|---|
| Smurf | ICMP와 브로드캐스트를 악용한 서비스 거부 공격 |
| Ping of Death | 비정상적으로 큰 ICMP 패킷 공격 |
| Land | 출발지와 목적지를 피해자 주소로 동일하게 설정 |
| DDoS | 다수의 장비에서 동시에 공격 |
| 랜섬웨어 | 파일을 암호화하고 금전을 요구 |
| 피싱 | 가짜 사이트나 메시지로 개인정보 탈취 |
| 사회공학 | 사람의 심리를 이용해 정보 획득 |

## 17. 접근통제

| 방식 | 기준 |
|---|---|
| DAC | 자원 소유자가 권한을 부여하거나 회수 |
| MAC | 보안 등급과 중앙 정책으로 강제 통제 |
| RBAC | 사용자의 역할이나 직무에 따라 권한 부여 |

```text
소유자 마음대로 → DAC
보안 등급·중앙 강제 → MAC
직무·역할 → RBAC
```

## 18. 인증과 인가

| 용어 | 의미 |
|---|---|
| 인증(Authentication) | 사용자가 누구인지 확인 |
| 인가(Authorization) | 확인된 사용자가 무엇을 할 수 있는지 결정 |

```text
로그인으로 본인 확인 → 인증
관리자 페이지 접근 허용 → 인가
```

### OTP

한 번만 사용할 수 있는 일회용 비밀번호다.

- TOTP: 시간 기반
- HOTP: 카운터 기반

### OAuth

사용자의 비밀번호를 제3자에게 전달하지 않고, 사용자가 승인한 범위의 접근 권한을 토큰으로 위임하는 방식이다.

```text
OTP → 일회용 인증값
OAuth → 접근 권한 위임
```

## 19. 암호화 핵심

| 방식 | 특징 |
|---|---|
| 대칭키 | 암호화와 복호화에 같은 키 사용, 속도가 빠름 |
| 비대칭키 | 공개키와 개인키 사용, 상대적으로 느림 |
| 해시 | 단방향 변환, 원문 복구 목적이 아님 |

### 대표 알고리즘

```text
대칭키: AES, DES, SEED, ARIA
비대칭키: RSA, ECC, ElGamal
해시: SHA, MD5
```

### 전자서명

```text
송신자가 자신의 개인키로 서명
수신자가 송신자의 공개키로 검증
```

목적:

- 인증
- 무결성
- 부인 방지

## 20. RAID

| RAID | 핵심 |
|---:|---|
| RAID 0 | 스트라이핑, 성능 향상, 장애 복구 불가 |
| RAID 1 | 미러링, 같은 데이터를 복제 |
| RAID 5 | 분산 패리티 1개, 디스크 1개 장애 허용 |
| RAID 6 | 분산 패리티 2개, 디스크 2개 장애 허용 |
| RAID 10 | RAID 1과 RAID 0 결합 |

```text
RAID 0 → 성능만
RAID 1 → 복제
RAID 5 → 패리티 1개
RAID 6 → 패리티 2개
RAID 10 → 복제 + 스트라이핑
```
