# 정규화와 반정규화

## 1. 정규화

정규화는 데이터의 일관성을 유지하고 중복을 최소화하기 위해 테이블을 분해하는 과정이다.

정규화의 목적은 이상 현상을 제거하고 데이터 구조를 더 안정적으로 만드는 것이다.

## 2. 이상 현상

### 1) 삽입 이상

원하지 않는 데이터까지 함께 입력해야만 데이터를 삽입할 수 있는 현상이다.

### 2) 갱신 이상

중복된 데이터 중 일부만 수정되어 데이터 불일치가 발생하는 현상이다.

### 3) 삭제 이상

특정 데이터를 삭제할 때 필요한 정보까지 함께 삭제되는 현상이다.

## 3. 정규화 단계

정규화 단계는 다음 순서로 진행된다.

```text
비정규 릴레이션
-> 제1정규형
-> 제2정규형
-> 제3정규형
-> BCNF
-> 제4정규형
-> 제5정규형
```

암기 키워드:

```text
원부이결다조
```

* 원자화
* 부분 함수 종속 제거
* 이행 함수 종속 제거
* 결정자 함수 종속 제거
* 다치 종속 제거
* 조인 종속 제거

## 4. 제1정규형

릴레이션에 속한 모든 속성의 도메인이 원자값으로만 구성되어 있으면 제1정규형이다.

즉, 하나의 칸에는 하나의 값만 들어가야 한다.

`ex) 연락처 컬럼에 010-1111-1111, 010-2222-2222처럼 여러 값이 들어가면 안 됨`

## 5. 제2정규형

제1정규형을 만족하면서 기본키가 아닌 모든 속성이 기본키 전체에 완전 함수 종속되면 제2정규형이다.

즉, 부분 함수 종속을 제거해야 한다.

`ex) 복합키 중 일부 컬럼에만 종속되는 속성은 별도 테이블로 분리`

## 6. 제3정규형

제2정규형을 만족하면서 기본키가 아닌 모든 속성이 기본키에 이행적 함수 종속되지 않으면 제3정규형이다.

즉, 비식별 속성 간의 종속 관계를 제거해야 한다.

`ex) 학생번호 -> 학과번호 -> 학과명 구조라면 학과 정보는 분리`

## 7. BCNF

BCNF는 릴레이션의 함수 종속 관계에서 모든 결정자가 후보키인 정규형이다.

즉, 후보키가 아닌 속성이 다른 속성을 결정하면 분리해야 한다.

## 8. 제4정규형

BCNF를 만족하면서 다치 종속을 제거한 정규형이다.

하나의 속성이 여러 개의 독립적인 다중값과 관련되는 경우 분리한다.

## 9. 제5정규형

제4정규형을 만족하면서 후보키를 통하지 않는 조인 종속을 제거한 정규형이다.

분해된 테이블을 다시 조인했을 때 원래의 테이블과 동일해야 한다.

## 10. 정규화와 성능

* 정규화는 데이터 중복을 줄여 입력, 수정, 삭제 성능을 향상시킬 수 있다.
* 하지만 테이블이 분리되기 때문에 조회 시 조인이 많아져 조회 성능이 떨어질 수 있다.
* 무조건 정규화가 좋은 것이 아니라 업무와 조회 패턴을 함께 고려해야 한다.

## 11. 반정규화

반정규화는 성능 향상과 개발/운영의 단순화를 위해 정규화된 테이블에 중복, 통합, 분리 등을 적용하는 기법이다.

데이터 무결성이 깨질 수 있으므로 신중하게 적용해야 한다.

## 12. 반정규화 적용 전 고려사항

반정규화는 바로 적용하는 것이 아니라 다음 방법을 먼저 검토한다.

1. 뷰로 해결 가능한지 확인
2. 인덱스로 해결 가능한지 확인
3. 클러스터링으로 해결 가능한지 확인
4. 파티셔닝이나 캐시로 해결 가능한지 확인

위 방법으로도 해결이 어려울 때 반정규화를 고려한다.

## 13. 반정규화 기법

### 1) 테이블 반정규화

* 테이블 병합
* 테이블 수직 분할
* 테이블 수평 분할
* 중복 테이블 추가
* 통계 테이블 추가
* 이력 테이블 추가
* 부분 테이블 추가

### 2) 컬럼 반정규화

* 중복 컬럼 추가
* 파생 컬럼 추가
* 이력 테이블 컬럼 추가
* PK에 의한 컬럼 추가

### 3) 관계 반정규화

* 중복 관계 추가
* 조인 경로를 줄이기 위해 이미 존재하는 관계를 추가로 구성

## 14. 핵심 정리

* 정규화는 중복과 이상 현상을 줄이기 위한 작업이다.
* 반정규화는 성능 향상을 위해 중복을 허용하는 작업이다.
* 정규화는 무결성에 유리하고, 반정규화는 조회 성능에 유리할 수 있다.
