# 데이터 모델링의 이해

## 1. 모델링의 특징

데이터 모델링은 현실 세계의 데이터를 일정한 기준에 따라 표현하는 작업이다.

1. 추상화
   * 현실 세계를 일정한 형식에 맞추어 간략하게 표현하는 것
   * 복잡한 업무를 핵심 개념 중심으로 뽑아내는 과정

2. 단순화
   * 복잡한 현실을 기호, 문자, 그림 등으로 쉽게 이해할 수 있게 표현하는 것
   * 누구나 같은 구조로 이해할 수 있도록 정리하는 과정

3. 명확화
   * 애매모호함을 제거하고 명확하게 현상을 기술하는 것
   * 하나의 의미로 해석되도록 표현하는 과정

## 2. 데이터 모델이 제공하는 기능

* 시스템을 가시화할 수 있게 해준다.
* 시스템의 구조와 행동을 명세화한다.
* 시스템을 만들기 위한 구조화된 틀을 제공한다.
* 시스템 구축 과정에서 문서화 역할을 한다.
* 다양한 관점에서 시스템을 바라볼 수 있게 한다.
* 상세 수준의 구체화를 가능하게 한다.

## 3. 데이터 모델링의 3단계

### 1) 개념적 데이터 모델링

* 추상화 수준이 가장 높은 모델링 단계
* 전사적 관점 또는 업무 관점에서 데이터 구조를 바라봄
* 엔터티와 속성을 도출하고 개념적 ERD를 작성하는 단계
* 업무 중심적이고 포괄적인 수준의 모델링

`ex) 고객, 상품, 주문 같은 주요 엔터티를 먼저 도출`

### 2) 논리적 데이터 모델링

* 특정 DB 모델에 맞춰 식별자, 속성, 관계 등을 정확하게 표현하는 단계
* 정규화를 통해 데이터 중복을 줄이고 재사용성을 높임
* 실제 테이블로 가기 전 논리적인 구조를 완성하는 과정

`ex) 고객번호를 식별자로 정하고 고객명, 연락처 등의 속성을 정의`

### 3) 물리적 데이터 모델링

* 실제 DB 구축을 위한 설계 단계
* 성능, 저장 공간, 보안, 가용성 등을 고려
* 테이블, 인덱스, 제약조건 등을 실제 DBMS에 맞게 설계

`ex) VARCHAR2, NUMBER 같은 데이터 타입 지정, 인덱스 생성`

## 4. 데이터 모델링의 관점

### 1) 데이터 관점

* 업무가 어떤 데이터와 관련되어 있는지 분석하는 관점
* 데이터 구조와 관계를 중심으로 모델링
* 정적 분석에 가깝다.

### 2) 프로세스 관점

* 업무가 실제로 어떤 일을 수행하는지 분석하는 관점
* 업무 처리 절차와 흐름을 중심으로 모델링
* 동적 분석에 가깝다.

### 3) 데이터와 프로세스의 상관 관점

* 프로세스가 데이터에 어떤 영향을 주는지 분석하는 관점
* CRUD 분석과 관련이 있다.

## 5. 좋은 데이터 모델링의 요건

1. 완전성
   * 업무에서 필요한 데이터가 빠짐없이 포함되어야 한다.

2. 중복 배제
   * 같은 데이터가 불필요하게 여러 곳에 저장되지 않아야 한다.

3. 업무 규칙 반영
   * 실제 업무 규칙이 데이터 구조에 제대로 반영되어야 한다.

4. 명확성
   * 다른 사람이 보더라도 같은 의미로 이해할 수 있어야 한다.
