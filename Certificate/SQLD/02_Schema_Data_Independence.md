# 스키마와 데이터 독립성

## 1. 스키마의 개념

스키마는 데이터베이스의 구조와 제약조건에 대한 정의를 의미한다.

데이터베이스는 사용자 관점, 전체 구조 관점, 저장소 관점으로 나누어 볼 수 있다.

## 2. 외부 스키마

* 사용자 관점의 스키마
* 개별 사용자나 응용 프로그램이 바라보는 데이터베이스 구조
* 전체 데이터베이스 중 사용자가 필요한 부분만 표현

`ex) 학생은 본인 성적만 조회하고, 관리자는 전체 성적을 조회하는 경우`

## 3. 개념 스키마

* 데이터베이스 전체 관점의 스키마
* 조직 전체의 데이터베이스 구조를 정의
* 모든 데이터를 통합하여 표현
* 데이터베이스 관리자가 관리하는 영역
* 데이터의 논리적 구조와 제약조건을 포함

`ex) 학생, 과목, 수강신청, 성적 테이블 간의 전체 관계`

## 4. 내부 스키마

* 저장소 관점의 스키마
* 실제 데이터가 물리적으로 저장되는 방법과 구조를 정의
* 데이터의 저장 경로, 인덱스, 저장 형식 등과 관련

`ex) 파일 저장 방식, 인덱스 구조, 물리적 접근 경로`

## 5. 데이터 독립성

### 1) 논리적 데이터 독립성

* 개념 스키마가 변경되어도 외부 스키마에 영향을 주지 않는 것
* 논리적 구조가 바뀌어도 사용자 화면이나 응용 프로그램의 변경을 최소화할 수 있다.

`ex) 테이블 구조가 일부 변경되어도 사용자가 보는 화면은 그대로 유지`

### 2) 물리적 데이터 독립성

* 내부 스키마가 변경되어도 개념 스키마에 영향을 주지 않는 것
* 저장 방식이나 인덱스 구조가 바뀌어도 논리적 테이블 구조는 유지된다.

`ex) 인덱스를 추가해도 테이블 구조나 SQL 사용 방식은 그대로 유지`

## 6. 핵심 정리

* 외부 스키마는 사용자 관점이다.
* 개념 스키마는 데이터베이스 전체 관점이다.
* 내부 스키마는 실제 저장소 관점이다.
* 논리적 독립성은 개념 스키마 변경과 외부 스키마의 독립성이다.
* 물리적 독립성은 내부 스키마 변경과 개념 스키마의 독립성이다.
