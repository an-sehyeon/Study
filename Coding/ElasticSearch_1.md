# Elasticsearch란?
* 엘라스틱서치(Elasticsearch)는 대용량 데이터를 실시간으로 검색하고 분석할 수 있는 검색 및 분석 엔진이다.
* Apache Lucene을 기반으로 하며, REST ful API를 제공해 JSON형식의 데이터를 저장하고 검색할 수 있다.
* 주로 로그 분석, 검색 시스템, 보안 데이터 분석 등 다양한 분야에서 사용되며, ELK(Stack) 핵심 요소로 사용된다.

## Elasticsearch가 빠른 이유는?
* 기존 RDBMS에서 %를 통해 데이터를 검색하는 경우에는 조회하려는 테이블의 데이터가 많아질수록 느려지는 구조를 가진다.
* 하지만 Elasticsearch는 역색인 구조를 사용해 검색 성능을 개선할 수 있다.

**💡 RDBMS에서 검색이 느린이유는?**
* RDBMS는 데이터를 행(row)단위로 저장하고 LIKE %검색어% 같은 연산을 사용해야 한다. 하지만 이 때 데이터가 많아질수록 문제가 발생한다.

<br>

**전체 테이블을 조회해야 한다(Full Table Scan)** <br>
* SELECT * FROM Product WHERE name LIKE %상품%
* 해당 검색어를 찾기 위해 모든 행을 탐색해야 함.
* 데이터가 많아질수록 검색 속도가 느려짐

**B-Tree 기반 인덱스의 한계** <br>
* RDBMS에서 INDEX를 사용해도, 문자열 검색에서는 효율이 떨어짐.
* 일반적인 인덱스는 정확한 값 검색에 최적화되어 있지만, 부분 문자열 검색에는 비효율적임.

<br>

**💡 그렇다면 Elasticsearch는 왜 빠를까?**
* Elasticsearch는 역색인(Inverted Index)구조를 사용해 데이터를 저장하고 검색한다.

1. 단어 단위로 인덱싱한다.
- 문장을 저장할 때, 단어(토큰)단위로 잘라서 색인을 생성
- 예를 들어 "빨간색 물결 악세서리" -> ["빨간색", "물결", "악세서리"]의 형태로 저장

2. 검색 시 단어 기반 매칭을 수행한다.
- 검색어 "빨간색"이 포함된 문서를 찾을 때, 역색인 테이블에서 즉시 해당 문서 목록을 반환
- 모든 문서를 일일이 비교할 필요가 없음
